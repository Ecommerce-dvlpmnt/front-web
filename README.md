# Front Web

Frontend интернет-магазина. Это отдельное Next.js-приложение, которое отвечает за
публичный интерфейс магазина: каталог, карточку товара, корзину, оформление заказа
и личный кабинет. Данные и бизнес-правила находятся в отдельном .NET API.

Проект находится на этапе визуального MVP: уже собраны общий layout магазина,
новогодний Hero, Header, Footer и переключатель светлой/тёмной темы. Архитектурные договорённости для дальнейшей работы
описаны в [docs/architecture.md](docs/architecture.md), а правила для команды — в
[AGENTS.md](AGENTS.md).

## Стек

- Next.js 16.4.3 и App Router
- React 19
- TypeScript в strict-режиме
- Tailwind CSS 4
- shadcn/ui и Radix UI для переиспользуемых компонентов
- pnpm 10
- .NET API — внешний backend проекта

Текущая визуальная тема — новогодняя. Сезонные тексты и промо лежат в
`src/lib/config/shop.ts`, поэтому позже тему можно заменить без переписывания
компонентов магазина.

## Быстрый запуск

Требования: Node.js, pnpm и запущенный .NET API (если страница использует данные
сервера).

```bash
pnpm install
cp .env.example .env.local
pnpm dev
```

После этого frontend доступен на [http://localhost:3000](http://localhost:3000).

Основные команды:

```bash
pnpm dev                 # development server
pnpm lint                # ESLint
pnpm exec tsc --noEmit   # проверка TypeScript
pnpm build               # production-сборка
pnpm start               # запуск production-сборки
```

Примечание: текущий шаблон использует `next/font/google`. В окружении без доступа
к `fonts.googleapis.com` команда `pnpm build` может завершиться ошибкой загрузки
шрифтов; для CI и offline-сборок шрифты нужно будет перенести в `next/font/local`.

## Подключение к .NET API

Адрес backend задаётся через `API_URL` в `.env.local`. Эта переменная предназначена
для серверной части Next.js и не должна иметь префикс `NEXT_PUBLIC_`, если в ней
есть закрытые данные.

```dotenv
API_URL=http://localhost:5000/api
```

Прямые запросы из браузера к .NET API допустимы только когда это действительно
нужно и на backend настроен CORS. В таком случае используется отдельная переменная
`NEXT_PUBLIC_API_URL`; секреты в неё помещать нельзя. Детали и рекомендуемая схема
слоёв описаны в [docs/architecture.md](docs/architecture.md).

## Структура проекта

```text
src/
  app/                  # маршруты, layouts, loading/error/not-found
  components/ui/        # базовые переиспользуемые UI-компоненты
  components/layout/    # Header, Footer, ThemeToggle
  components/home/      # Hero и блоки главной страницы
  components/           # общие компоненты интерфейса
  features/             # код конкретных доменов: catalog, cart, auth, checkout
  hooks/                # только общие клиентские hooks
  lib/api/              # единая точка работы с .NET API
  lib/config/           # конфигурация магазина и сезонного контента
  lib/                  # утилиты
  types/                # типы DTO и frontend-модели
public/                 # статические файлы
docs/                   # архитектурные и командные договорённости
```

Не нужно создавать все папки заранее. Новая папка появляется вместе с первой
реальной задачей в соответствующей области.

## Рабочий процесс

Перед началом работы прочитайте [AGENTS.md](AGENTS.md). Для каждой задачи:

1. Убедитесь, что рабочее дерево не содержит чужих незакоммиченных изменений.
2. Делайте небольшие изменения, относящиеся к одной задаче.
3. После изменений запускайте `pnpm lint` и `pnpm exec tsc --noEmit`.
4. Перед объединением ветки запускайте `pnpm build`.
5. В описании PR указывайте, что изменилось, как проверить и какие ограничения
   остались.

Для UI-задач отдельно проверьте мобильный Header, открытие меню и обе темы —
светлую и тёмную. После перезагрузки выбранная тема должна сохраниться.

## Статус

На текущем этапе приложение — визуальный каркас с новогодней темой. Реализация
каталога, экранов магазина и интеграция с .NET API выполняются поэтапно после
согласования API-контрактов.
